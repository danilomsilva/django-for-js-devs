# Appendix — Glossary

Short definitions of Django/DRF terms used across the guide, each with a link back to the chapter that introduces it properly. If a term surprised you somewhere and you just want a quick reminder, this is the page.

**ASGI** — the newer, async-capable server protocol Django supports, alongside WSGI. See [04 — Request lifecycle](04-request-lifecycle.md), [24 — Deploy](24-deploy.md).

**`APIView`** — the lowest-level DRF view class; you write each HTTP method yourself. See [10 — DRF intro](10-drf-intro.md).

**App** — a self-contained feature module within a Django project (e.g. `greetings/`). See [03 — Project anatomy](03-project-anatomy.md).

**`django_assert_num_queries`** — a pytest-django fixture that asserts exactly how many database queries a block of code runs; used to catch N+1 regressions. See [19 — N+1 queries](19-n-plus-1-queries.md).

**Filter backend** — a DRF component that turns query params into ORM filters (e.g. `DjangoFilterBackend`). See [14 — Pagination, filtering, ordering](14-pagination-filtering-ordering.md).

**Middleware** — an ordered function that wraps every request/response, run before and after the view. See [04 — Request lifecycle](04-request-lifecycle.md).

**Migration** — a generated Python file describing a schema change, applied with `migrate`. See [07 — Migrations](07-migrations.md).

**MTV** — Django's own name for its architecture (Model-Template-View), where confusingly "View" means controller. See [02 — Django philosophy](02-django-philosophy.md).

**N+1 query problem** — running one query per row in a loop instead of fetching everything upfront; fixed with `select_related`/`prefetch_related`. See [19 — N+1 queries](19-n-plus-1-queries.md).

**Non-field error** — a validation error that doesn't belong to a single serializer field, keyed as `non_field_errors` in a DRF error response. See [15 — Errors & validation](15-errors-and-validation.md).

**OpenAPI schema** — a machine-readable description of an API's endpoints, generated by `drf-spectacular` from your views/serializers. See [16 — Typed contracts](16-typed-contracts.md).

**Permission class** — a DRF class deciding whether a request is *allowed* to do something, distinct from authentication. See [13 — Permissions](13-permissions.md).

**Project** — the overall Django configuration (settings, root URLs) — one per codebase, containing one or more apps. See [03 — Project anatomy](03-project-anatomy.md).

**QuerySet** — a lazily-evaluated representation of a database query, built by chaining methods like `.filter()`. See [06 — Models & ORM](06-models-and-orm.md).

**`related_name`** — names the reverse accessor a `ForeignKey` adds to the related model. See [06 — Models & ORM](06-models-and-orm.md).

**Serializer** — validates incoming data and shapes outgoing data between Python objects and JSON. See [11 — Serializers](11-serializers.md).

**Settings module** — the Python module (`config/settings.py`) holding all of a Django project's configuration. See [09 — Settings & environments](09-settings-and-environments.md).

**`transaction.atomic`** — wraps a block of code so every write inside it commits together or rolls back together. See [20 — Transactions](20-transactions.md).

**`uv`** — the Python package/dependency/version manager used throughout this guide, playing the role `npm`/`nvm` play together in JS. See [00 — Intro](00-intro.md).

**View** (Django's meaning) — the request-handling logic; what you'd call a controller or route handler in Express. See [02 — Django philosophy](02-django-philosophy.md), [05 — URLs & views](05-urls-and-views.md).

**ViewSet** — a DRF class bundling a full set of CRUD operations for a resource into one class, paired with a router. See [05 — URLs & views](05-urls-and-views.md), [10 — DRF intro](10-drf-intro.md).

**WSGI** — Django's original, synchronous server protocol. See [04 — Request lifecycle](04-request-lifecycle.md), [24 — Deploy](24-deploy.md).
